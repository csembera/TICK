Targeted Intelligence Companion Kit
(TICK)

TICK watches public job boards for a list of target accounts and turns their postings into a dashboard and a brief per account. Source discovery happens once: the evaluator finds a company's job-posting endpoint and writes it down as a SourceConfig. That config then becomes the input for a deterministic collector that runs on serverless infrastructure every night, building a historical data lake of job postings and the hiring insights drawn from them.

What TICK gives you

Accounts overview
Every tracked company on one page: open roles, the change over the past week, tech-role count and the date of the last crawl.
Hiring dashboard
The technology each account is hiring for, split into newly adopted and established, beside a searchable table of open roles and a trend of the board over time. Rebuilt every night.
Weekly AI brief
Every Sunday night, an AI agent reads the week's changes for each account and writes a brief on what moved. Movement in leadership, new initiatives the company is staffing for, technologies showing up for the first time, and what to do about them.

The whole system

Collection runs across the middle, publishing along the bottom. The lake between them is the only thing they share.

Inside the evaluator agent

The evaluator turns a company name into a verified SourceConfig. It is a Strands agent running Claude on Amazon Bedrock, and it runs once per company, plus again whenever that company's collection starts failing. The model decides where to look; plain code decides when the run stops and whether the result can be trusted.

Inside one collection

What the collector does with a single queue message. It has no company-specific code: the SourceConfig in the message decides everything.

  1. 1

    Fetch

    The config's ats field picks the branch.

    • workday: POST in pages of 20, up to 100 pages
    • adp: one list call, then a detail GET per req, merged in
    • greenhouse · lever · ashby · other: one GET; postings_key names the array
    postings[], total_reported
  2. 2

    Normalize

    schema_map paths such as bulletFields[0] turn each posting into a curated row.

    • No stable id: hash of company + title + location
    • Relative URLs are joined onto careers_url
    rows[]
  3. 3

    Enrich

    Pulls in the description, then matches keywords in the title and description.

    • Workday: one detail GET per posting
    • ADP: already merged in step 1
    • description_field: read from the listing itself, no extra request
    • 8 keyword categories; is_tech_role is set by any hit outside signal terms and analytics tools
    rows[].keywords
  4. 4

    Diff

    Compares today's ids with state.json to find new, closed and reopened postings, then stamps first_seen and last_seen.

    Drift guard0 rows but open reqs in state → raise → retry → DLQ
    new · closed · reopened
  5. 5

    Write

    Five objects, partitioned by company= and dt=:

    • raw postings
    • curated rows
    • snapshot diff
    • updated state
    • tech-stack summary
    s3 put × 5

Inside the publisher

Two jobs put pages on the site. The publisher rebuilds every dashboard each night, and a brief agent writes each account's brief once a week from what changed.

Every night: dashboards

  1. 1

    Find accounts

    Reads every SourceConfig in configs/ and picks out the accounts with at least one crawl. A first crawl's dashboard shows the open board alone, with change figures from the next crawl on.

    accounts[]
  2. 2

    Compare

    Measures the latest crawl against the most recent one at least 7 days older, so the numbers show a week's drift rather than overnight noise.

    • Short history falls back to the oldest crawl, labeled with its real date
    • Terms first seen in the last 6 months count as newly adopted
    opened · closed · reopened
  3. 3

    Render

    Builds one dashboard per account from the comparison.

    • Hiring stack, newly adopted vs. established
    • Searchable open-roles table, new roles flagged
    • Open-role trend and tech roles opened
    Nothing inventedEvery number traces to a posting, snapshot count or diff
    <slug>/dashboard.html
  4. 4

    Publish

    Writes each dashboard to the private site bucket, where only CloudFront can read it.

    • Cached for 5 minutes, so a reload soon shows fresh numbers
    • An empty lake fails the run instead of publishing a blank site
    s3 put × dashboards

Every Sunday night: briefs

  1. 1

    Start

    EventBridge starts the brief agent once a week, on Sunday night, for each account.

    company_slug
  2. 2

    Read the week

    Loads the account's week of diffs from the lake: roles opened, closed and reopened, with the postings and stack terms behind them.

    diffs · postings · stack
  3. 3

    Reason

    A Strands agent running Claude on Bedrock works out what the week means for the account.

    • Leadership seats filled or newly opened
    • New initiatives the company is staffing for
    • Technology appearing for the first time
    findings + citations
  4. 4

    Write the brief

    Writes a short summary of the week with suggested next steps.

    Grounded in the lakeEvery claim cites the posting or snapshot it came from; anything the week's data can't support is left out
    <slug>/brief.html
  5. 5

    Publish

    Writes each brief to the private site bucket next to the account's dashboard, where only CloudFront can read it.

    • Replaces the previous week's brief
    • Cached for 5 minutes, like the dashboards
    s3 put × briefs
